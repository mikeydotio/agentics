# Module: plugins/atlas/tests (chunk 3)

## Purpose

This module holds bash test suites that exercise atlas v2's incremental update machinery end-to-end against the real CLI: ledger diff/finalize, index rebuild, doc apply-renames/remove, and status tiering across edit, rename, delete, conflict-marker, and corrupt-frontmatter scenarios, plus the separate verify-cache write/read persistence layer that lets `/atlas repair` reuse a prior `/atlas verify`. Each test builds a throwaway git fixture repo, mutates it, and asserts the CLI plans and applies exactly the affected docs — proving hash-gating, ripple propagation to dependents, and byte-identical untouched docs/INDEX rows. If this module vanished, atlas's edit/rename/delete/conflict/corruption update paths and the verify-cache staleness gates would have no regression coverage.

## Type notes

- Each test function owns a fresh, isolated throwaway git fixture repo built by `_update_fixture` or `_vc_fixture` and torn down at the end via `cleanup_fixture_repo` (plugins/atlas/tests/test-update-flow.sh:13, 101, 137, 179, 219, 239, 262; plugins/atlas/tests/test-verify-cache.sh:10, 58, 73, 88, 103, 115, 139, 155) — no state or fixture repo is shared across tests.
- `_vc_write` (plugins/atlas/tests/test-verify-cache.sh:27-34) invokes the CLI directly with piped stdin rather than the shared `run_atlas` helper, since `verify-cache write` reads its verdicts JSON from stdin, not argv.
- `_index_body` (plugins/atlas/tests/test-update-flow.sh:44-46) encodes the invariant that INDEX.md's freshness/baseline-SHA line is the only part expected to change on every update; everything else must be byte-stable when no summary/read_when/fact changed.
- `_VC_VERDICTS` (plugins/atlas/tests/test-verify-cache.sh:36) is the single shared verdict payload fixture reused by every verify-cache round-trip test.

## Gotchas

- `verify-cache write` reads verdicts from stdin, so this suite bypasses the shared `run_atlas` helper and shells out to `python3 "$CLI" verify-cache write` directly instead (plugins/atlas/tests/test-verify-cache.sh:26-34).
- The INDEX byte-stability check strips the "Generated by atlas" line before comparing, because that baseline-SHA line is expected to legitimately change on every update while everything else must stay byte-identical (plugins/atlas/tests/test-update-flow.sh:41-46).
- `test_verify_cache_version_mismatch_is_invalid` bumps only the cache's stored `version` while keeping the fingerprint correct, isolating proof that the version gate (not the fingerprint gate) is what rejects an unrecognized cache format (plugins/atlas/tests/test-verify-cache.sh:123-137).
